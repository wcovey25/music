GROUP A - NETWORKING & SPEED
 A1. [core/netconn.py] One shared requests.Session pool for all threads (no cookies), happy-eyeballs (RFC 8305)
     connecting that remembers the working address family, DNS cache (~60 s), prewarm() of hosts a run will use.
 A2. [core/netstats.py] Per-host smoothed RTT + variation (RFC 6298), recent-latency median/p95, connect times,
     counters (calls, failures, hedges, cache hits). Thread-safe, no network.
 A3. Rework core/netio.py to use A1/A2: host-fitted timeouts, hedged second request when a call exceeds the host's
     usual tail, merging of identical simultaneous lookups, short answer cache, free retry on a stale connection.
     KEEP everything existing (adaptive limiter, Retry-After, circuit breaker, resumable + segmented downloads, Memo)
     and my iTunes 403 handling.
 A4. [resources.py, telemetry/monitor.py, telemetry/stats.py] Hardware scan (cores, memory, measured connection),
     plan() = songs at once + concurrent encodes, Budget gates, Governor (only for >=10 songs; every ~2 s: add one
     worker if everything is busy and throughput really rose, remove on errors/site pushback/saturated CPU, rest 4 min
     after a failed attempt; on battery fewer workers; battery saver -> max 2). Windows readings in
     musicdl/platform_.py: logical cores, CPU load (overall and per core), memory (ctypes GlobalMemoryStatusEx), power
     (GetSystemPowerStatus); no thermal data (report "nominal" and say so in the README). Mirror the Mac
     platform_.py function names/signatures. "Automatic" off => the user's number is a ceiling. The progress card says
     "Easing off ..." when holding back. Keep autotune.py working as a fallback. Test with simulated readings.

GROUP B - SEARCH & MATCHING
 B1. [core/closematch.py] Near-match offers for songs not found exactly (reuse already-fetched results, then title
     alone, then artist + words + "lyrics"), each labelled ("Live version", "0:42 longer", "Uploaded by ...").
     Never offer karaoke, tutorials, reactions, nightcore/slowed/8D, mashups, hour-long loops. Setting "Close
     matches": Ask (default; Attention row gets a "Choose..." button and one prompt at end of run), Auto (only same
     song/artist within 25% length), Off. A recording the user picks is accepted regardless of length.
 B2. [ingest/suggest.py + ui/views_source.py] Source bar doubles as search bar: Deezer public-search suggestions
     (songs/albums/artists/playlists/genres), ranked by coverage, popularity, exactness, penalising cover/karaoke/
     remix unless typed. Up/Down/Return/Esc; dropdown UI; offline = silent no-op. collect(): song, album, artist top
     songs, playlist (first 300), genre chart.
 B3. [core/quality.py, audio/sampler.py, config.py, ui/views_advanced.py] "Match the source" switch in Advanced
     (default on) and hi-res fake detection (a 96 kHz/24-bit file made from CD audio is not written bigger). Merge with
     my existing quality.fit/sampler; keep the documented limits (detects ~64-192 kbps origins, believes >=224).

GROUP C - SOUND & TAGS
 C1. [audio/process.py, audio/transcode.py] analyze() once, then ONE ffmpeg filter chain in the encode pass: EBU R128
     loudness normalisation + limiter, silence trim with soft fade, fade in/out, EQ presets (clarity, warmth, bass,
     vocal), dynamics setting. Optimized mode: one switch "Polish every song". Advanced: a "Sound" tab.
 C2. "Clean versions" setting (Settings > Songs, default off): prefer clean uploads (about one extra YouTube query per
     song). The tag side (rtng 1/2 etc.) already exists - verify it, add only the setting and the search change.
 C3. Make sure nothing ported regresses the metadata/artwork pipeline (section 1).

GROUP D - INTERFACE (match the existing glass look; check screenshots in light/dark, small/large, 150% DPI)
 D1. [ui/painter.py, ui/viz.py, ui/dashboard.py] Live tab (Advanced): speed ribbon (real speed, average, peak,
     required-pace dotted line), time left as a RANGE, one pillar per CPU core, per-song stage slots + legend,
     per-server latency bars (from netstats), searches/min, errors/retries, memory. Layout is a pure function of size
     (compact/regular/wide, never overlapping). Pictures drawn on a worker thread (Pillow only), swapped in on the UI
     thread, redrawn only when numbers change enough.
 D2. [ui/card3d.py] Tilting artwork card: perspective transform from a true rotation of four corners, sheen, moving
     shadow, tilt quantised to quarters (<= 9x9 cached images), eases back on leave.
 D3. [ui/spectrum.py] Advanced > Format spectrum: bars up to the format's cut-off, a glowing node that glides on
     change, dynamic range from bit depth.
 D4. Settings: Motion (Full/Reduced; Reduced stops all animation from D1-D3 and the splash); keep the app's own
     synthesised sounds (no Apple system sounds on Windows); port the improved launch animation [ui/splash.py] but
     keep it Windows-safe.
 D5. [ui/welcome.py] First-run walk-through: step 1 song folder, step 2 protection (see E1, optional). Skip the

 D6. [ui/icon.py] Generated app icon (Pillow, several sizes) plus a multi-size .ico used for the window, taskbar and
